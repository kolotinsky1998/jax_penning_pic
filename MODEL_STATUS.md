# Текущая физическая и вычислительная модель

> Статус документа: описание фактически реализованного кода на ветке `main`, commit `56f4a7f` от 2026-09-21.  
> Главный исполняемый сценарий: `SimulationCircleGyroNEW`.  
> Этот файл описывает не желаемую модель, а текущее поведение программы. Места, где физическая корректность еще требует проверки, явно помечены как **требует верификации**.

## 1. Назначение и границы модели

Код реализует электростатическую particle-in-cell (PIC) модель разряда Пеннинга в круговой двумерной области. Частицы имеют две пространственные координаты и три компоненты скорости (2D3V). Самосогласованно решается двумерное уравнение Пуассона; магнитное поле задается внешним, постоянным и направленным по оси `z`.

В модели присутствуют:

- электроны и однозарядные положительные ионы;
- постоянное однородное магнитное поле `Bz`;
- самосогласованное электростатическое поле `(Ex, Ey)`;
- круглая граница-анод с нулевым потенциалом;
- горячий центральный катод и кольцевая область холодного катода;
- эмиссия электронов, уход частиц и столкновения с неподвижным фоновым газом;
- фиксированные по размеру массивы макрочастиц и маска `alive`, пригодные для JAX/JIT/GPU.

Не реализованы: электромагнитная динамика поля, нейтралы как частицы, `Ag/Pb`-компоненты, межчастичные кулоновские столкновения, restart/checkpoint, multi-GPU и адаптивная сетка.

## 2. Геометрия, размперность и масштабирование

### 2.1 Геометрия

Расчетная сетка квадратная, `nx = ny`, `dx = dy`. Физическая область для Пуассона задается дискретной маской

```text
(x - xc)^2 + (y - yc)^2 < R_anode^2.
```

Узлы вне круга считаются заземленной внешней областью. Для прямого, CG и Jacobi решателей это соответствует условию Дирихле `phi = 0` вне круга и, следовательно, на его дискретной границе.

Код использует следующие области:

| Область | Радиус в коде | Назначение |
|---|---:|---|
| Анод / граница расчета | `(nx - 1) dx / 2` | Частица удаляется после выхода из круга |
| Начальное плазменное пятно | `0.3 nx dx` | Начальное распределение электронов и ионов |
| Горячий катод | `0 .. 0.01 * scale` | Область горячей электронной эмиссии |
| Холодный катод | `0.01 * scale .. 0.15 * scale` | Удаление ионов и вторичная эмиссия |

Круг и положение частиц непрерывны, а поле хранится на декартовой сетке. Отдельной геометрии электродов в решателе Пуассона нет: центральные катоды влияют через источники/стоки частиц, но не задают внутренние граничные условия для потенциала.

### 2.2 Масштабированная задача

Перед расчетом применяется набор преобразований, перенесенный из референсного сценария:

```text
R_model = R * scale
B_model = B / scale
n_e,model = n_e / scale
n_i,model = n_i / scale
n_gas,model = n_gas / scale
I_hot,model = I_hot * scale
I_cold,model = I_cold * scale
```

При значении по умолчанию `scale = 0.02` радиус `0.26 m` превращается в `0.0052 m`, а `B = 0.1 T` — в `5 T`. Это не безразмерная запись: в ядрах далее используются SI-константы и эти масштабированные величины.

**Требует верификации:** в репозитории нет вывода подобия, доказывающего сохранение всех определяющих безразмерных параметров при этих преобразованиях. При изменении `scale` необходимо отдельно проверять времена, длины свободного пробега, токи и макровес.

## 3. Макрочастицы и начальное состояние

Каждый вид хранится в отдельном массиве фиксированной емкости (`max_electrons`, `max_ions`). Слот содержит:

```text
x, y;
vx, vy, vz;
Ex, Ey;
Bx, By, Bz;
vx_c, vy_c, vz_c;
alive.
```

`v_c` — скорость ведущего центра, используемая для перемещения электронов. У ионов она синхронизируется с обычной скоростью при Boris update.

Начальные электроны и ионы:

- создаются попарно в одинаковых точках равномерно по площади диска инжекции;
- используют одинаковые случайные нормированные векторы скорости, но разные тепловые масштабы из-за массы;
- компоненты скорости берутся из нормального распределения, обрезанного условием `|z| < 3`;
- масштаб скорости равен `sqrt(2 E_init / (3m))`, где по умолчанию `E_init = 0.1 eV`;
- получают отрицательный полушаг скорости перед первым полноценным шагом (электроны — gyro update, ионы — Boris update), то есть используется leapfrog-подобная временная центровка.

Число начальных макрочастиц одного вида:

```text
N_seed = floor(pi * (R_injection/dx)^2 * ptcls_per_cell), минимум 1.
```

Макровес вычисляется так, чтобы начальная плотность в диске была `n_e,model / 10`:

```text
W = (n_e,model / 10) * pi * R_injection^2 / N_seed.
q_macro,e = -e W
q_macro,i = +e W.
```

Это двумерная постановка с трансляционной инвариантностью по `z` и неявной единичной длиной по этой оси. Формально `W`, полученный как объемная плотность, умноженная на площадь, следует интерпретировать как число частиц на единицу длины `z`; заряд осаждается как `q_macro/(dx dy)`.

## 4. Один временной шаг

Фактический порядок операций в основном JIT-ядре:

```text
1. CIC-осаждение rho_e и rho_i
2. Формирование rho = rho_e + rho_i и, по умолчанию, фильтрация rho = filter(rho)
3. Решение уравнения Пуассона
4. Вычисление Ex, Ey на сетке
5. CIC-интерполяция поля на частицы
6. Gyro-push электронов на dt
7. Boris-push ионов на dt
8. Электронные столкновения, если наступил их интервал
9. Ионные столкновения, если наступил их интервал
10. Удаление электронов и ионов на аноде
11. Заданный током сток ионов на холодном катоде
12. Горячая электронная эмиссия
13. Холодная вторичная электронная эмиссия
14. Увеличение номера шага
```

Следствия порядка операций:

- поле шага вычисляется по положениям частиц до их перемещения;
- столкновения применяются после перемещения;
- новые эмитированные и созданные при ионизации частицы впервые участвуют в осаждении заряда и push на следующем шаге;
- частицы, покинувшие анод после push, удаляются в том же шаге до следующего осаждения.

## 5. Осаждение заряда, интерполяция поля и фильтр плотности

### 5.1 CIC / билинейная схема

Для осаждения заряда и сбора поля используется одна и та же линейная билинейная форма (cloud-in-cell, CIC) по четырем соседним узлам:

```text
w00 = (1-hx)(1-hy)
w10 = hx(1-hy)
w11 = hx hy
w01 = (1-hx)hy.
```

Индексы базовой ячейки ограничиваются диапазоном `[0, n-2]`. Мертвые частицы дают нулевой вклад. Отдельной коррекции весов около круглой границы нет.

### 5.2 `rho_filter_new`

По умолчанию к суммарной плотности заряда применяется двухпроходный девятиточечный фильтр внутри диска:

1. сглаживание с весами `center:axis:diagonal = 4:2:1`, нормировка `1/16`;
2. компенсирующий sharpening-проход с весами `20:-1:-1`, нормировка `1/12`.

Первый проход подавляет сеточный шум, второй частично восстанавливает амплитуду/высокочастотную составляющую. Свертка реализована через `jnp.roll`. Вне маски фильтра возвращается исходная `rho`, однако решатели с круговой маской затем не используют внешнюю плотность.

Фильтр можно отключить при запуске флагом `--disable-rho-filter`. В этом режиме в решатель Пуассона без дополнительного сглаживания передается `rho = rho_e + rho_i`. Значение сохраняется в `metadata.json` как `config.use_rho_filter`; по умолчанию оно равно `true`.

**Численная особенность:** маска фильтра строится вокруг индексного центра `nr_anode`, тогда как геометрическая маска Пуассона центрирована в `0.5 * nx * dx`. Для текущего определения сетки между центрами есть сдвиг в половину шага. Это следует проверить при строгом сравнении симметрии.

## 6. Уравнение Пуассона и электрическое поле

Решается электростатическое уравнение

```text
-nabla^2 phi = rho / epsilon_0,
E = -grad(phi).
```

Используется стандартный пятиточечный конечно-разностный оператор второго порядка на равномерной сетке. Соседи вне круговой маски эквивалентны `phi = 0`.

Доступны четыре backend-а:

| `poisson_solver` | Реализация | Критерий/стоимость | Практическое замечание |
|---|---|---|---|
| `direct_inverse` | На CPU один раз строится плотная матрица оператора по внутренним узлам и ее полный inverse; на каждом шаге выполняется matvec | Подготовка примерно `O(Nu^3)`, память и шаг `O(Nu^2)` | Значение по умолчанию; точное для собранного дискретного оператора с учетом float32, но плохо масштабируется по сетке |
| `cg` | Предобусловленный conjugate gradient, диагональный (Jacobi) предобуславливатель | До `poisson_iterations`; остановка по относительной норме residual `< poisson_tol` | Использует `phi` прошлого шага как начальное приближение |
| `jacobi` | Weighted Jacobi | Ровно `poisson_iterations` итераций, `omega = poisson_omega` | `poisson_tol` не используется; warm start от `phi` прошлого шага |
| `fft_capacitance` | Периодическая FFT Green function плюс capacitance correction на дискретной границе | FFT на шаге и плотная граничная коррекция; оператор строится один раз | Матрица коррекции регуляризуется; `phi` вне круга не зануляется явно, поэтому backend требует отдельной валидации |

Для неизвестного имени solver функция фактически провалится в Jacobi, хотя CLI разрешает только четыре перечисленных значения.

`direct_inverse` строит inverse в `float64` через NumPy, затем переводит его в `float32`. Основные поля и частицы также хранятся в `float32`.

Поле вычисляется центральной разностью второго порядка:

```text
Ex[i,j] = (phi[i-1,j] - phi[i+1,j]) / (2 dx)
Ey[i,j] = (phi[i,j-1] - phi[i,j+1]) / (2 dy).
```

На внешних границах квадратного массива используются односторонние разности. На криволинейной границе специальной нормальной аппроксимации нет.

## 7. Движение частиц

### 7.1 Электроны: gyro / guiding-center push

Для электронов поле раскладывается относительно локального `B`, вычисляется дрейф `E x B`, параллельная скорость ускоряется полем `E_parallel`, а перпендикулярная скорость поворачивается на циклотронный угол. Положение обновляется не полной скоростью, а скоростью ведущего центра:

```text
r_new = r_old + v_c * dt.
```

В текущей геометрии `B = (0,0,Bz)` и `E = (Ex,Ey,0)`, поэтому `E_parallel = 0`; самосогласованное поле дает поперечный `E x B`-дрейф. Гирофаза и полная 3D-скорость сохраняются для столкновений, но ларморовское движение не разрешается в координатах явно.

**Требует верификации:** гирофаза восстанавливается через `acos(v_perp,x / |v_perp|)`, который не различает знаки `v_perp,y`, после чего перпендикулярная скорость явно собирается в плоскости `xy`. Для текущего `B || z` второе ограничение ожидаемо, но потеря квадранта гирофазы может давать неверный поворот даже в этой геометрии. Автоматического orbit-теста сейчас нет.

Электронный шаг:

```text
dt_e = gyro_coeff / (10 * omega_ce),
omega_ce = e B_model / m_e.
```

То есть `gyro_coeff` намеренно укрупняет шаг относительно базового `1/(10 omega_ce)`; это допустимо вычислительно благодаря аналитическому повороту, но является физико-численным приближением ведущего центра.

### 7.2 Ионы: Boris push

Ионы двигаются обычным 3D Boris pusher-ом в `(E,B)`, а координаты обновляются полной скоростью `vx, vy`. Ионный push выполняется на каждом шаге модели с тем же интервалом `dt`, что и электронный push:

```text
dt_ion = dt_electron = dt.
```

Отдельный ионный subcycling и величины `dt_i`/`ion_step` не используются. Масса, заряд, электрическое и магнитное поля, а также сам алгоритм Boris не изменены; изменена только временная дискретизация движения ионов. Начальный отрицательный полушаг скорости ионов соответственно равен `-dt/2`.

## 8. Столкновения с фоновым газом

Фоновый газ не представлен частицами. Его физическая плотность вычисляется из идеального газа `n_gas = p/(k_B T_gas)`, затем используется масштабированная `n_gas/scale`. Таблицы сечений линейно интерполируются по энергии; вне табличного диапазона берется крайнее значение.

Столкновения применяются пакетно, не каждый шаг:

- электроны: раз в `collision_step_electron`, вероятность считается на полном интервале `collision_step_electron * dt`;
- ионы: раз в `collision_step_ion`, вероятность считается на полном интервале `collision_step_ion * dt`.

Используется линейная аппроксимация вероятности `P = nu Delta t`, а не `1 - exp(-nu Delta t)`. Вероятности явно не ограничиваются единицей.

### 8.1 Упругое электрон-нейтральное столкновение

Для энергий до `100 eV` берется табличное сечение `e-Ar_elastic.txt`. Для энергий выше `100 eV` используется аналитическая формула рассеяния на аргоне (`Z = 18`). В промежутке от последней точки таблицы (примерно `35.9 eV`) до `100 eV` используется постоянное последнее табличное значение.

```text
P_el = sigma_el(E) * n_gas,model * |v| * Delta t.
```

Азимутальный угол случаен. Полярный угол выбирается по разным формулам ниже и выше `100 eV`; учитывается малая потеря энергии на отдачу тяжелого нейтрала. После столкновения обновляются и полная скорость, и скорость ведущего центра.

### 8.2 Электрон-ударная ионизация

Используется таблица `e-Ar_ionization.txt` и

```text
P_ion = sigma_ion(E) * n_gas,model * |v| * Delta t.
```

Один общий uniform random number выбирает взаимоисключающий канал:

```text
r < P_el                    -> elastic
P_el <= r < P_el + P_ion    -> ionization.
```

При ионизации у первичного электрона вычитается ровно `16 eV`, направление скорости сохраняется. В той же точке создаются один новый электрон и один новый ион с нулевыми скоростями. Событие и счетчик засчитываются только если одновременно есть свободный слот в обоих пулах.

Не моделируются распределение остаточной энергии между двумя электронами, углы вылета и recoil нейтрала/иона.

### 8.3 Ион-нейтральное столкновение / charge exchange

Используется `Ar+-Ar_elastic.txt`. Нейтральная скорость сэмплируется из трехмерного Maxwell distribution при `T_gas`.

**Требует верификации — существенное место:** текущая функция вероятности возвращает

```text
P_i = sigma_i(E) * n_gas,model * Delta t
```

без множителя относительной скорости. Это размерностно не является вероятностью столкновения для обычной модели `n sigma v Delta t`.

После принятия события код с вероятностью 1/2 выбирает «elastic» или charge exchange. Однако при равных массах используемая формула elastic-ветви алгебраически сводится к установке скорости иона равной сэмплированной скорости нейтрала — тому же результату, что и ветвь charge exchange. Поэтому сейчас обе ветви фактически эквивалентны полной перезарядке/термализации иона. Это необходимо сверить с C++ reference.

Масса фонового нейтрала не является отдельным параметром: в электронном recoil и ионной Maxwell-скорости используется `config.m_ion`. Поэтому сканирование искусственного отношения `m_i/m_e` одновременно меняет массу нейтрала, хотя таблицы сечений остаются аргоновыми.

## 9. Источники, стоки и границы частиц

### 9.1 Анод

После push все электроны и ионы за пределами круглой области деактивируются. Счетчик `Ntot_anode_leave` учитывает только ушедшие электроны; ушедшие на анод ионы удаляются, но отдельным счетчиком не фиксируются.

### 9.2 Сток ионов на холодном катоде

Из живых ионов в кольце холодного катода случайно удаляется заданное током количество. Целевой ток

```text
I_ion_leave = I_cold,model / (1 + gamma).
```

Число событий за интервал переводится в число макрочастиц через `e * W`. Дробная часть накапливается между событиями.

### 9.3 Горячая и холодная эмиссия

Горячая эмиссия задается `I_hot,model`. Вторичная холодная эмиссия задается средней скоростью `gamma * I_ion_leave`, а не фактическим количеством ионов, удаленным на конкретном шаге. Для горячего диска радиус `R sqrt(u)` дает равномерное распределение по площади. Для холодного кольца реализовано `r_min + (r_max-r_min)sqrt(u)`, что не является равномерным по площади annulus; корректная формула для этого была бы `sqrt(r_min^2 + u(r_max^2-r_min^2))`.

Новые электроны имеют `vx = vy = 0`, `vz > 0` с энергией `100 eV`.

**Конфигурационная особенность:** поля `energy_emission_hot_ev` и `energy_emission_cold_ev` существуют, но функции источников их не получают; обе энергии жестко зашиты как `100 eV`. При заполненном электронном пуле лишняя эмиссия теряется.

Для всех токовых событий дробный остаток сохраняется, но нехватка доступных частиц для стока или свободных слотов для эмиссии не образует backlog: недовыполненная целая часть теряется.

## 10. Параметры по умолчанию и производные значения

Основные входные значения:

| Параметр | По умолчанию |
|---|---:|
| `scale` | `0.02` |

Если `grid_size` не задан, шаг выбирается равным удвоенному вычисленному радиусу Дебая, а число узлов — целой части диаметра, деленного на этот шаг. `T_e` и `T_i` используются именно для этого расчета сетки; они не задают начальные скорости частиц, для которых используется `init_energy_ev`.

При явном `--grid-size N` код сохраняет модельный диаметр и ставит `dx = 2 R_model / N`; дебаевский критерий тогда не используется.

## 11. JAX- и вычислительные особенности

- Основное состояние — неизменяемые `NamedTuple`; шаг возвращает новое состояние.
- Массивы частиц имеют фиксированную форму, жизненный цикл задается `alive`; динамического append/remove нет.
- Основной режим компилирует один шаг через `jax.jit`, а затем объединяет шаги в JIT-блоки через `lax.fori_loop`.
- Размер блока — `gcd(log_interval, field_dump_interval)`, чтобы синхронный I/O выполнялся между блоками.
- Конфигурация и число шагов блока являются static arguments: их изменение вызывает отдельную компиляцию.
- Профилировочный режим выполняет Python loop и синхронизирует каждую стадию; его производительность не равна основному режиму.
- PRNG функциональный, стартует с `seed`; одинаковая конфигурация и backend обычно воспроизводимы в пределах гарантий JAX/устройства.
- Большинство вычислений — `float32`; счетчики — `int32`. При очень длинных запусках счетчики могут переполниться после примерно `2.1e9` событий.
- Поиск свободных слотов и некоторые выборки работают по полной емкости пула, а не только по живым частицам.
- При полном пуле новые частицы молча не записываются. Специальной диагностики saturation нет.

## 12. Выходные данные и диагностика

В `output_dir` записываются:

```text
metadata.json       полная конфигурация и режим исполнения
counters.csv        числа частиц и интегральные счетчики
rho_e_<step>.txt    осажденная электронная плотность заряда до фильтра
rho_i_<step>.txt    осажденная ионная плотность заряда до фильтра
phi_<step>.txt      потенциал
profiling.csv       только в подробном profile-режиме
profiling_summary.json
```

`counters.csv` содержит `ne`, `ni`, числа частиц внутри горячего катода и накопленные `Ntot_ionized`, `Ntot_cold_cathode_leave`, `Ntot_anode_leave`, `Ntot_hot_cathode_emission`.

Суммарная отфильтрованная `rho`, `Ex/Ey`, фазовые координаты частиц, энергия и баланс заряда штатно не сохраняются. Restart из дампов невозможен.

## 13. Что реально проверено тестами

В тестах есть содержательные проверки:

- построения положительной геометрии и явного `grid_size`;
- валидации положительного `ion_mass_ratio` и флага отключения фильтра плотности в CLI;
- безопасной записи в свободные слоты;
- одинаковых начальных позиций/нормированных скоростей электронов и ионов;
- накопления дробного остатка токовых событий.

Файлы тестов для deposition, Poisson, collisions и gyro push сейчас являются placeholder-ами и проверяют только `assert True`. Полноценной численной регрессии шага, закона сохранения заряда/энергии и сравнения с C++ нет. `scripts/compare_with_cpp.py` пока является заготовкой.

На машине, где составлен этот документ, тесты не были запущены: в системном Python отсутствуют `jax` и `pytest`. Поэтому данный раздел отражает чтение тестового кода, а не успешный test run.

## 14. Текущий статус и приоритеты верификации

### Реализовано и подключено в основном сценарии

- полный PIC-цикл deposit → Poisson → gather → push;
- четыре backend-а Пуассона;
- electron guiding-center/gyro push и ion Boris push на каждом шаге;
- электронное elastic-рассеяние, ионизация, ионный collision channel;
- анодные потери, холодный ионный сток, горячая и вторичная эмиссия;
- фиксированные particle pools, JIT-блоки, диагностика и profiling;
- CLI-сканы сетки, числа частиц и искусственной массы иона через SLURM scripts.

### Наиболее важные открытые вопросы

1. Исправить или обосновать отсутствие `|v_rel|` в ионной collision probability.
2. Проверить и развести elastic/CX кинематику: сейчас обе ветви дают практически один результат.
3. Проверить восстановление гирофазы через `acos` полноценным orbit-тестом; при необходимости заменить на `atan2` или векторный поворот.
4. Перейти с `nu dt` на `1-exp(-nu dt)` или доказать малость всех вероятностей; добавить контроль `P_el + P_ion <= 1`.
5. Привязать энергии эмиссии к конфигурации и исправить выборку радиуса холодного кольца.
6. Отделить массу нейтрала от искусственной массы иона либо документировать требуемое подобие.
7. Верифицировать `scale`-преобразования и ускоренный `gyro_coeff` по безразмерным параметрам.
8. Сравнить все Poisson backend-ы на одной `rho`, включая residual, граничное значение и поле.
9. Добавить физические regression tests: сохранение осажденного заряда, аналитические задачи Пуассона, Boris/gyro orbit, статистику столкновений, source/sink balance.
10. Реализовать количественное сравнение с C++ по критериям из `SPEC.md`.
11. Добавить диагностику переполнения пулов, потерянной эмиссии/ионизации и недовыполненного стока.
12. Уточнить полуклеточный сдвиг между маской фильтра и геометрической маской.
